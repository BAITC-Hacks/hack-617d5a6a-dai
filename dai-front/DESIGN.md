# Дизайн интерфейса и схема сети

К чему пришли по UI: продукт, экраны, граф, визуальный язык. Решения из дизайн-сессии 23.09 сверены с контрактом бэкенда (`openapi.json`): где решению не хватает поля в API, это сказано рядом. Эндпоинты, поля и запуск — в [README](README.md).

Пометки: **[Решено]** — договорились, **[Предложение]** — не утверждено, **[TBD]** — открытый вопрос. Предложение становится решением только после обсуждения в команде.

## Продукт

**[Решено]** Инструмент класса investigation / link analysis (не мониторинг транзакций и не KYC). Главный вопрос экрана: «кого из 2 248 клиентов смотреть первым и почему». Рабочее место аналитика: очередь приоритетов → граф → карточка узла. Граф — один из инструментов, а не главный экран.

**Демо-сценарий [Решено]:** обзор → очередь приоритетов → клик по №1 → карточка с обоснованием роли и путём от seed → жюри называет `gid` → поиск → окружение узла со связями → (позже) мультивыбор и вопрос ассистенту → ответ подсвечен на графе → в перечень.

**Порядок реализации [Решено]:**

1. Карточка узла с обоснованием роли
2. Очередь приоритетов (топ-лист)
3. Поиск `gid` + окружение узла с направлением денег
4. Кластеры
5. AI-ассистент и нарративы
6. Таймлапс, устойчивость сети, визуальная полировка

## Экраны

Язык UI — русский. Десктоп 1440–1920 px, показ на проекторе: высокий контраст, крупные цифры. **[Решено]**

### Рабочее место (главный экран, три колонки) [Решено]

- **Слева — очередь проверки** (узлы с `in_queue` из `/graph`, по убыванию `priority_score`; `/top` отдаёт только 50): номер в очереди, `gid`, бейдж роли, `priority_score` числом и мини-баром, `evidence` в две строки. Под заголовком — правило очереди из `/meta` (`queue_rule`). Фильтры: роль, кластер, только seed, скрыть оборванные. Чекбокс «в перечень».
- **Центр — схема сети** (ниже, раздел «Схема сети»): поиск `gid`, режимы «Вся сеть / Кластер / Окружение узла», легенда, мини-карта.
- **Справа — вкладки «Карточка / Ассистент».**
- Выбор узла в любой колонке синхронизирует остальные: выбранный `gid` в URL, hover — в `src/stores/graph-view.ts`.

### Карточка узла (`/nodes/{gid}`)

| Блок | Что показывать | Откуда |
|---|---|---|
| Шапка | `gid`, роль, `role_score`, `priority_score`, кластер, колено, seed-статус, «№ N в очереди», «признаки быстрого транзита · N пар» | `node`, `in_queue`, `fast_transit_flag`, `fast_transit_pairs` |
| Почему такой приоритет | два наибольших вклада в скор (признак, значение, перцентиль, вклад), сколько признаков выше P95, сырой скор | `score_terms`, `n_terms_above_p95`, `priority_raw` |
| Почему эта роль | `evidence` как есть | `node.evidence` |
| Потоки | топ входящих и исходящих контрагентов (`gid`, сумма, `n_tx`), кликабельные; вход/выход с оговоркой при неполном балансе | `in_edges`, `out_edges`, `in_kzt`/`out_kzt` |
| Хронология | переводы июля по датам; пары «вход → выход» по дате входа со статусом хронологии и отметкой «1-к-1» (быстрый транзит) — нейтральное наблюдение, не тревога. Точность — день, порядок внутри дня неизвестен | `transfers`, `pairs` |
| Связь с делом | «деньги от N seed сходятся в этот узел»; пути seed → … → узел с суммами | `n_seed_upstream`; пути — **нет в API** |
| Чек-лист правила | «отправителей 24 ≥ 3 ✓»; у периферии — текст «ближе всего …, поддержка …» | `role_checks` |
| Качество данных, что запросить дальше | ограничения данных по узлу, рекомендуемый следующий запрос | `limitations`, `next_request` |
| Кнопки | «В перечень», «В чат», «Сформировать справку» | фронт |

### Прочие экраны

- **Обзор сети:** KPI (узлы, seed, рёбра, оборот, кластеры) из `/meta`, распределение по ролям и коленам, блок «Ограничения данных» с числами, топ-5.
- **Кластеры** (`/clusters`, `/clusters/{id}`): таблица (узлов, seed, оборот, `top_gids`, `hypothesis`, мини-стек ролей) + подграф кластера и ключевые узлы.
- **Перечень на проверку** [Предложение]: отобранные узлы + заметки аналитика, экспорт CSV и текста, дисклеймер о гипотетичности. Формат экспорта — [TBD].
- **Устойчивость сети** [Предложение]: ползунок «изъять топ-N» (0–50) → число компонент, размер крупнейшей, доля отрезанных seed.

## Схема сети

**[Решено]** Эстетика и поведение Obsidian Graph view, адаптированные под AML. Библиотека: D3 (d3-force, d3-zoom, d3-drag, d3-transition). Реализация — `src/components/graph/money-graph.ts` (порт движка из макета Claude Design), панель — `graph-panel.tsx`. Сейчас все виды на SVG, см. «Производительность».

### Визуал

- Тёмный фон, маленькие круглые узлы, тонкие полупрозрачные серые связи. Цвет только у смысловых элементов.
- Цвет узла — роль (переключатель «Раскрасить по: роли / кластеру»), размер — `priority_score`.
- Seed — контрастная обводка + лёгкая пульсация. Обрыв выборки (`truncated_by_depth`) — пунктирная обводка, не путать с «Конечным получателем».
- Подписи `gid`: у топ-20 всегда, у остальных появляются при зуме (порог в настройках, по умолчанию ×1,6). В подписи — средняя часть `gid`, полностью в тултипе. Экранный размер ограничен: обычные подписи и подписи кластеров — до 12 px, выбранный узел — до 14 px; дальше при приближении текст не растёт. Перекрывающиеся подписи скрываются (первыми остаются наведённый, выбранный, затем по `priority_score`).
- Выбранный и наведённый узел — свечение; при наведении соседи и их связи подсвечены цветом узла.
- Кластеры — «острова» в общем виде: оболочки `d3.polygonHull` со скруглением, слабая заливка, подпись «Кластер 3 · 23 из 42 узлов» (видимых из паспорта).

### Физика

- `forceLink` (distance ~30, strength ~0.4), `forceManyBody` (~-40), `forceCollide` (r + 2), `forceX/forceY` к центру кластера (~0.08), чтобы кластеры читались островами. Значения стартовые, подбираются на данных.
- Раскладка должна быть готова до первого кадра, чтобы граф не «взрывался» при загрузке. В API координат нет: прогреваем симуляцию (300+ тиков) до рендера, потом плавное проявление. Если на 2 248 узлах это долго — просим у бэкенда `x`, `y`.
- Drag: `alphaTarget(0.3).restart()` на старте, фиксация через `fx/fy`, остывание после отпускания.

### Взаимодействие

- **Hover:** узел и соседи — 100 %, остальное за 150 мс гаснет до ~12 %, связи до ~4 %. Соседи предрасчитаны в `Map<gid, Set<gid>>`. Тултип: `gid`, роль, приоритет, вход/выход.
- **Поиск `gid`:** перелёт камеры `zoom.transform` за ~750 мс + пульс-кольцо.
- **Направление денег:** `src → dst`, стрелка обязательна. Бегущий пунктир (`stroke-dasharray` + анимация `stroke-dashoffset`) — только у подсвеченных и выбранных связей, на общем виде без анимации.
- **Смена фильтра или режима:** fade + подогрев симуляции (`alpha(0.3)`), без скачков.
- Подсветка ответа AI и лассо работают поверх этого же графа.

### Окружение узла (local graph)

- Глубина — ползунок 1–4 хопа. Окружение считается на клиенте по всему `/graph` (граф грузится один раз), `/subgraph` не нужен.
- Переключатели «Откуда пришли деньги» / «Куда ушли деньги» / «Связи между соседями».
- По умолчанию укладка слоями слева направо по направлению денег (по `depth`), переключатель на force.

### Панель настроек графа (свёрнута по умолчанию)

- Фильтры: роли (клик по легенде), кластеры, «seed без связей», «скрыть обрыв выборки».
- Отображение: стрелки / бегущий пунктир, порог подписей, размер узлов, толщина связей (`sum_kzt`).
- Forces для демо: отталкивание, длина связей, притяжение к кластеру.

### Таймлапс [Предложение]

Таймлайн 01.07–31.07.2026 под схемой: гистограмма переводов по дням и кнопка ▶. Связь появляется в день первого перевода, узел — с первой связью. Ползунок и диапазон дат фильтруют граф. Сделано по переводам из уже открытых карточек узлов (связи без дат остаются бледными). **Нужно от бэкенда:** дата первого перевода у ребра в `/graph`, чтобы таймлапс покрывал всю сеть.

### Производительность [Решено]

- 2 248 узлов + 3 119 связей + физика в SVG — это ≈5 тыс. DOM-элементов на тик. План был: общий вид — Canvas, детальные виды — SVG.
- Сейчас общий вид тоже SVG: первый кадр ~1 с, раскладка оседает за несколько секунд (~10 fps), наведение ~50–75 мс. Для демо достаточно; окружение узла (десятки узлов) работает плавно. Если на проекторе будет тормозить — узлы и рёбра общего вида перенести на Canvas, подписи и ореолы оставить в SVG.
- «Уменьшить движение» в ОС: без анимаций, раскладка досчитывается сразу, направление — стрелками.
- Бегущий пунктир — только на подсвеченных связях.
- [Предложение] Если Canvas не вытянет общий вид — WebGL (Sigma.js / react-force-graph).

## AI поверх графа

**[Решено]** Роли, скоры и кластеры считает детерминированный пайплайн по правилам с порогами. AI только объясняет, пишет нарративы и гипотезы, отвечает на вопросы — роли и скоры не меняет. В UI:

- каждый AI-текст помечен значком и подписью «сгенерировано по метрикам графа, требует проверки»;
- каждое утверждение заземлено: `gid`, метрика или правило рядом — кликабельный чип;
- «факт из данных» визуально отличается от «гипотезы» (отдельный стиль, метка «Гипотеза»);
- при недоступности LLM — шаблонный текст по метрикам и пометка «AI недоступен».

**Чат [Предложение]:** узлы в контексте — чипы над полем ввода (`● gid Консолидация ×`, цвет точки — роль). Добавить: `A` на выбранном, лассо + `A`, контекстное меню, drag & drop, `@gid`, `@cluster:3`. Ответ: `gid` — кликабельные чипы (hover подсвечивает на графе), блок «Источники», кнопка «Показать на графе» подсвечивает подграф ответа, пути цепочкой `seed → … → узел` с суммами, честный отказ при нехватке данных.

**Нужно от бэкенда [TBD]:** эндпоинта для AI нет. Предложенный формат ответа: `{ text, citations: [{gid|metric|rule}], highlight: {nodes, edges} }` — фронт рендерит чипы и подсветку по `highlight`. Провайдер LLM и где живёт агент — не решено.

## Визуальный язык

**[Решено]** Уровень Linear / Vercel / Palantir: нейтральная основа, яркий цвет только у смысловых элементов. Основная тема тёмная, контраст проверяется на проекторе. Моноширинный шрифт для `gid` и сумм. Суммы `4 215 000 ₸`, крупные `4,2 млн ₸`. Даты `ДД.ММ`.

**Тон [Решено]:** только гипотезы — «признаки консолидации», «кандидат в координаторы», «рекомендуется проверить». Никаких «преступник», «организатор» без оговорки.

**Роли и цвета [Предложение — финальные токены из макетов Claude Design]:**

| Роль | Подпись | Смысл | Цвет | Глиф |
|---|---|---|---|---|
| `coordinator` | Координатор | кандидат в организаторы | фиолетовый | ◆ |
| `consolidator` | Консолидация | аккумулирует средства от многих | красный | ● |
| `distributor` | Распределитель | веерная рассылка | оранжевый | ✱ |
| `transit` | Транзит | пропускает дальше | янтарный | → |
| `terminal` | Получатель без видимых исходящих | исходящих в выгрузке не видно | синий | ■ |
| `peripheral` | Периферия | признаков не выявлено | серый | · |

- Подписи ролей для легенды отдаёт `/meta` (`roles[].title`); таблица выше — про цвет и глиф.
- Цвета ролей и кластеров — токены в `src/index.css` (`@theme`), не хардкод в компонентах.
- Seed — статус, не роль: обводка/глиф поверх цвета роли.
- Кластеры — своя категориальная палитра, не конфликтующая с ролями.
- Цвет никогда не единственный носитель смысла: глиф или подпись обязательны.

**Референсы:** Obsidian Graph view (основной для графа) · Unit21, Flagright (очередь + экран кейса, AI-нарративы) · Quantexa (сеть вокруг сущности) · Chainalysis Reactor, Elliptic Investigator (поток слева направо, суммы на рёбрах) · KeyLines/ReGraph (combos, глифы, time bar) · Palantir Gotham (связанные представления).
