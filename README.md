# DAI — «Граф денег»

Командный репозиторий HackAlem AI. Цель кейса — восстановить проверяемую структуру финансовой сети по направленному графу переводов: роли узлов, группы, денежные потоки и приоритеты проверки.

## Состояние

Пайплайн (`pipeline/`, метод v1 по умолчанию) считает по трём parquet роли по опубликованным правилам с порогами, кластеры (Louvain на явной ненаправленной проекции), единый приоритет с порогом и обоснование с числами для каждого из 2 248 узлов и записывает три CSV схемы ТЗ за ≈2 с; выгрузки проходят 45 проверок `pipeline/check.py`, повторный прогон даёт байт-в-байт тот же результат. Приоритет: сумма по семи фактам о переводах (суммы, число плательщиков и получателей, посредничество, сквозная сумма, достижимость от исходных клиентов) вклада «минус логарифм доли узлов с не меньшим значением», плюс отметка быстрого транзита (вход и выход похожей суммы за 0–2 дня, не меньше двух пар); в `evidence` — два факта с наибольшим вкладом. Временной признак проверен перестановкой дат (`python -m pipeline.temporal_check --data task/data`): 54 узла против 34–38 в контроле. Стартовый код организаторов в `task/starter/` оставлен без изменений.

## Запуск

Пайплайн, без Docker (Python 3.11–3.13):

```bash
make setup      # .venv и зависимости из requirements.txt
make pipeline   # task/data/*.parquet → outputs/nodes_roles.csv, clusters.csv, top_nodes.csv (≈2 с)
make check      # проверка выгрузок по схеме ТЗ, код возврата 1 при нарушении
```

То же без make:

```bash
python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
python -m pipeline.run --data task/data --out outputs
```

Интерфейс: `make api` (FastAPI на 8000, читает `outputs/`; без выгрузок отдаёт заглушку с пометкой `mock`) и в другом терминале `make web` (http://localhost:5173). Подробнее: [backend/README.md](backend/README.md), [dai-front/README.md](dai-front/README.md). Пороги ролей, порядок их выбора и порог приоритета — в `pipeline/rules.py` (функция `print_thresholds()` печатает таблицу для README), они же записываются в `outputs/run_meta.json`. Запасной метод v0 (только пороги стартовых гипотез): `python -m pipeline.run --data task/data --out outputs --method v0`.

## Основной сценарий (цель)

1. Аналитик получает от правоохранительных органов 81 известный `gid`.
2. Пайплайн по выгрузке переводов на 4 колена присваивает каждому из 2 248 узлов роль, кластер и приоритет с обоснованием.
3. В интерфейсе аналитик ищет `gid`, видит направление переводов, роль и её основание, открывает топ-лист и решает, кого проверять первым.

Выводы о клиентах — гипотезы для проверки, а не утверждения о виновности.

## Проверка исходного стартового кода

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r task/starter/requirements.txt
python task/starter/starter.py --data task/data --out scratch/starter
```

`scratch/` — временный вывод для проверки, не сдача.

## Критерии готового решения

- Один локальный запуск от исходных Parquet до трёх CSV за 5 минут на обычном ноутбуке. Для обязательного расчёта не нужны платный API, GPU или секретный ключ.
- `nodes_roles.csv`: все 2 248 узлов, объяснимые роли и числовые основания; `clusters.csv`: группы и гипотезы; `top_nodes.csv`: минимум 20 приоритетных узлов.
- Интерфейс показывает направление переводов, роли и связи произвольного `gid` за время демо.
- Правила назначения ролей, пороги, ограничения выборки и план масштабирования описаны в README/`docs/`. Выводы о клиентах формулируются как гипотезы для проверки.

`gid` хранится как `int64` в данных и обязательных CSV. При передаче идентификаторов в браузер используйте строки: некоторые значения больше безопасного целого JavaScript.

Секреты хранятся только локально в переменных среды или `.env`; `.env` не коммитится. Опциональные LLM-функции не должны быть нужны для воспроизведения обязательного результата.
