# Приёмка решения «Граф денег»

Состояние на 23.09.2026: контрольные клиенты выбраны по `outputs/nodes_roles.csv` и `outputs/top_nodes.csv`. Числа ниже проверены по CSV после введения правила очереди. Запуск из чистого клона проверен. Проверка карточек в браузере пока не записана. После изменения расчёта нужно повторить выбор и сверку.

## Что проверяет аналитик

1. Ввести `gid` из таблицы ниже в поиск.
2. Проверить направление стрелок и даты переводов в окрестности клиента.
3. Сравнить роль, два основания приоритета и ограничения в карточке с таблицей ниже.
4. Прочитать следующий запрос и за минуту объяснить, какие данные нужны для проверки версии.

Роль описывает видимые переводы. `priority_raw` задаёт порядок проверки, а не вероятность нарушения. Статус «быстрый транзит» означает совпадение сумм и дат по правилу модели. Он не устанавливает, что через счёт прошли те же деньги.

## Текст о приоритете для README и карточки

Приоритет помогает выбрать, кого проверить первым. Семь показателей описывают суммы переводов, число разных плательщиков и получателей, положение клиента между другими клиентами, меньшую из входящей и исходящей сумм и число исходных клиентов, связанных с ним по графу. Редкое значение даёт больше баллов. Повторные пары переводов похожей суммы за 0–2 дня добавляют один балл к сумме. Клиент попадает в очередь проверки, если хотя бы два из семи показателей входят в верхние 5 % среди 2 248 клиентов. Сумма баллов задаёт порядок внутри очереди и за её пределами. Значение 6 баллов служит справочным порогом суммы и не определяет очередь. Список `top_nodes.csv` содержит 50 клиентов независимо от очереди. Баллы не показывают вероятность нарушения. В карточке приведены два показателя с наибольшим вкладом.

`priority_score` в обязательном CSV лежит в пределах 0..1. Справочный порог 6 относится к `priority_raw`. Поле `in_queue` отмечает фактическое включение в очередь по двум показателям в верхних 5 %.

## Тексты следующего запроса

В `pipeline/evidence.py` есть шесть веток, включая отдельную ветку для изолированного seed. Строки ниже внесены в код. Каждая начинается с действия и короче 120 знаков.

| Ситуация | Текст |
| --- | --- |
| Глубина 4 | Запросить исходящие переводы клиента за июль 2026: на 4-м шаге их не собирали. |
| Seed | Запросить полные входящие переводы клиента, включая отправителей вне выборки. |
| Исходящий перевод датирован раньше сопоставленного входящего | Запросить остаток перед ранним исходящим переводом и поступления до него. |
| Быстрый транзит | Запросить назначения сопоставленных платежей и остатки на даты их проведения. |
| Изолированный seed | Запросить переводы клиента меньше 5 000 KZT и операции с другими банками за июль. |
| Остальные | Запросить выписку и сведения о контрагентах для крупнейших переводов клиента. |

Для роли `terminal` в карточке нужно показывать «получатель без видимых исходящих». Роль `coordinator` означает связь ветвей наблюдаемого графа. Она не устанавливает, кто управляет счетами.
